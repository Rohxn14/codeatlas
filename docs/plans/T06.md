# T06 plan: Python resolver

## Approach and data structures

`PythonResolver.resolve(results, index)` works only from `ParseResult`s and the symbol index (no source text, no file access). Four small modules under `resolver/`:

- `project.py` finds modules. A file set plus roots (`""`, `src`, every package root from T15's package nodes read through `index.by_key(package_key)`, and the importer's own folder). `find_module("a.b", roots)` checks `root/a/b.py` and `root/a/b/__init__.py`. Several matches: those in the importer's own package win, otherwise all, and confidence is 1 ÷ matches. Relative imports climb `level - 1` folders from the importer's package folder.
- `symbols.py` builds, per module, the top-level definitions, the import bindings (`name → module | symbol | external`, resolved lazily so re-exports are followed up to 3 hops) and per-class info (bases, methods, MRO).
- `refs.py` resolves a dotted text (`BaseRepo`, `os.path.join`, `UserRepo.save`) to a `Ref` (nodes, module paths, or an external name) by walking one part at a time.
- `calls.py` applies the levels in order; `resolver.py` wires imports, calls, inherits and tests.

## Rule per level (example from the fixture)

- IMPORTS: `from .repo import Repo as BaseRepo` → `repo.py::Repo`; a variable (`CALL_LOG`, `router`) → its module; `import pytest` → `::external:pytest`.
- DIRECT 1.0: bare name defined here or imported (`dispatch(...)` in `routes.list_users`); decorator `@logged`; `UserRepo()` → inherited `Repo.__init__`; `HTTPException(...)` → `::external:fastapi.HTTPException`; `len` → `::external:builtins.len`.
- SELF_METHOD 0.9: `self.all()` in `UserRepo.find_by_name` → `Repo.all` via bases; `super().save` → `Repo.save`; typed receivers (below).
- IMPORT_SCOPED 1÷n: `service.get_user(id)` in `routes.get_user`, receiver untyped: methods named `get_user` in routes.py and the files it imports → only `UserService.get_user`.
- NAME_GUESS 1÷n capped at 0.3: same-named methods anywhere (`obj.save()` with `save` in three classes → 0.3).
- Raw: `func(*args)` (a parameter), `HANDLERS[name](..)`, `getattr(..)()`, module-level calls.

## Decisions

1. **Typed receivers: `SELF_METHOD` 0.9.** The method is found through a class's MRO exactly like `self.m()`, and a declared type can still be a subclass that overrides it, so not 1.0. No contract change. Type sources: `self.X` where the class's `__init__` has a parameter `X` annotated with a class (the `self.repo = repo` convention; the adapter does not emit assignments, so the name match is the evidence), a parameter annotation (`service: UserService`), `Cls(...).m()` and `f().m()` with a return annotation.
2. **Local variables: no.** `x = Foo(); x.run()` needs assignments, which the raw items do not carry; those calls fall to IMPORT_SCOPED, which usually finds `Foo.run` anyway. Asked in the PR: should the adapter emit local assignments?
3. **Name-guess cut-off: more than 5 candidates stays raw.** Q2 in `decisions.md` is unanswered. At 5 the confidence is 0.2; beyond it the guess is mostly noise. Also never guessed: method names of builtin containers and strings (`get`, `append`, `items`...) and the caller itself.
4. **MRO:** depth-first, left to right, each class once, depth 10, bases imported from other files followed. An unresolvable base (external or unknown) is skipped and marks the MRO incomplete: a method not found then stays raw instead of being guessed.

## Tests

Multi-file samples in `tests/data/python_resolver/`, exact edges for every table row, relative/absolute/`src/` imports, `__init__` re-exports (and the 3-hop limit), aliases, inherited `__init__`, `super()`, builtin, external, a 3-candidate name guess (0.3), ambiguous modules (1÷2), each raw case, TESTS edges. In-memory `GraphStore` and `symbol_index`; plus the fixture score.

## What I expect to get wrong

Duck typing and locals (`client.get` stays raw or guessed), `self.x` set outside `__init__`, module-level instances (`service = UserService(..)`, found only by IMPORT_SCOPED), conditional imports, `from m import *`, property/descriptor attributes, same-named methods in sibling classes (IMPORT_SCOPED splits the confidence).
