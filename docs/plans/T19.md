# T19 plan: CLI commands and README

All new commands live in `src/codeatlas/cli.py` and reuse `_open_store` (the `--db`
default is `<data_dir>/codeatlas.db`, as for `view`; `--snapshot` defaults to the latest
snapshot). Each takes `--json`, which prints one JSON object and nothing else on stdout.

- `search "query" [-k 10] [--no-expand] [--embed]`: `HybridSearch(store, snap,
  EmbeddingClient.from_config())`. Text: one line per hit, `rank  score  kind  key
  path:line  [bm25+vector]`, then the search notes. `--embed` builds missing embeddings
  first; a failure there is a note, and BM25 still answers.
- `ask "question" [--max-steps 20]`: if neither `GROQ_API_KEY` nor `GEMINI_API_KEY` is
  set, print one line naming both and exit 2 before opening anything. Otherwise
  `agent.loop.ask`; print the answer, each citation as `ok`/`INVALID` (with the reason),
  steps and tokens, and the trajectory path. An `LLMError` exits 1.
- `impact` and `tests` share one input group (exactly one required):
  - `--diff FILE` or `--diff -` (stdin): the text goes to `impact.diff.parse_diff`;
  - `--git REV`: run `git -C <root> diff REV --` and parse that. The root comes from the
    snapshot's `source`, resolved the same way the agent's tools do
    (`ToolContext.repo_root`: the local folder, or the clone of a URL). Only git runs;
    nothing from the repository;
  - `--files a.py b.ts`: one whole-file `Change` per path (backslashes turned into `/`).
  Options `--depth`, `--decay` go into `ImpactConfig`; `--top 20` cuts the printed list.
  - `impact` prints the changed symbols, then `rank  score  kind  key` with one evidence
    line under each (signal, and the hop path `a <-calls 0.9- b` or the detail), then the
    warnings.
  - `tests` prints the ranked test picks with evidence, then the test files at the
    engine's cut-off (`ImpactConfig.test_threshold`) and the share of the snapshot's test
    files skipped (`impact.evaluate.all_test_files`).
  - A change that maps to nothing still exits 0 with the engine's warnings.
- `mcp`: the same as `python -m codeatlas.agent mcp` (`serve_stdio(ToolSet(...))`), but
  with the CLI's `--db` default.
- `view --impact FILE`: the diff file is run through the engine; the page gets an
  `impact` block (changed keys, top targets with scores) shown as a section above the
  explorer, and the graph colours changed and target nodes.

Errors (no database, bad snapshot, unreadable diff, git failing) print `codeatlas: ...`
and exit 2, as the existing commands do.
