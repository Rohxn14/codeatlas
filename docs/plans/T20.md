# T20 plan: typed receivers for TypeScript and JavaScript

Goal: a receiver whose type is declared (`repo: UserRepo`, `@param {UserRepo} repo`,
`constructor(private repo: UserRepo)`, `repo = new UserRepo()`) resolves `repo.save()`
to `UserRepo.save` at `SELF_METHOD` 0.9, as T06 does for Python (D-22). Everything else
behaves exactly as today.

## Type sources, most trusted first

1. **TypeScript annotations in the stored `signature`** of the caller and of every
   function around it (nearest first): `(repo: UserRepo)`. The signature text is parsed
   by a small bracket-aware splitter (no re-parse of the file): first top-level `(...)`,
   split on top-level commas, drop `public/private/protected/readonly/override`, `...`
   and defaults; destructured parameters (`{ a }: Opts`) are skipped.
2. **Class fields, for `this.x`**: a new `attrs["fields"]` on CLASS nodes
   (field name → type text, `""` when declared without any type). Filled in
   `symbols.py` from `repo: UserRepo;` (annotation), `/** @type {UserRepo} */ repo;`
   (JSDoc), `repo = new UserRepo()` (initialiser) and, in the constructor body,
   `this.repo = new UserRepo()` and `/** @type {UserRepo} */ this.repo = ...`. This is
   the one `symbols.py` change: the class signature stops at `{`, so the fields are not in
   any text already stored. Constructor parameter properties
   (`constructor(private repo: UserRepo)`) are read from the constructor's stored
   signature; when nothing else names `this.repo`, a constructor parameter of the same
   name supplies the type (the same convention T06 uses for `self.repo = repo`, and the
   usual JavaScript shape). The class and then its INHERITS chain are searched, nearest
   first.
3. **JSDoc in the stored `docstring`**: `@param {UserRepo} repo` (also `[repo]`,
   `[repo=x]`), `@type {UserRepo}` on fields; `@template T` adds a type parameter.
   An annotation wins over JSDoc for the same parameter.
4. **`new Foo()` assigned to a local name**: the adapter does not record assignments,
   so this source is skipped (the brief allows it only if already recorded).

Chains go one hop per declared type: `this.a.b.m()` takes the type of `this.a`, then the
`b` field of that class. Return types (`const r = make()`) are not used.

## From type text to a class node

`type_name(text)`: strip JSDoc markers (`?X`, `!X`, `X=`) and outer parentheses; split
the top-level union and drop `null`, `undefined`, `void`; exactly one member must remain.
Then `Name` or `ns.Name` with optional generic arguments (`Repo<User>` → `Repo`). Not a
class: intersections, arrays (`X[]`, an array's methods are built-ins), `Promise<X>`
(a receiver call on a promise is `then`/`catch`; we never see the `await`), object,
function and literal types, `typeof X`, `any`, `unknown`, primitives, and any name that
is a type parameter of the caller, the functions around it or the class
(`<T>`, `@template T`). The remaining name goes through the existing `NameResolver`
(local top-level symbols, import bindings, `ns.X`), so aliases (`import {A as B}`),
re-exports and barrels work for free. It must land on a CLASS node.

## Resolving the method

The method is looked up on the class and its INHERITS chain with the existing
`_find_method`; found → `SELF_METHOD` 0.9. Not found and the class has a base outside
the repository → no edge (same as `this.m()` today). Not found otherwise → fall through
to today's behaviour. A typed receiver is tried before DIRECT so a typed parameter
shadows an import of the same name, and before the built-in stop-list, because with a
known class `cache.get()` really is `Cache.get`. The stop-list, the 5-candidate cut-off
and D-23 stay for untyped receivers.

## What stays untyped

A name whose nearest declaration has no usable type (an untyped inner parameter shadows
a typed outer one), `any`/`unknown`, unions of two classes, type parameters, arrays,
promises, interfaces, locals, return types, `import("./x").Y` JSDoc types.

**Interfaces**: interface method signatures are not nodes today (`symbols.py` creates
none, and contract `owner_key` is "key of the class for a method"), so there is nothing
for the "interface's declaration" edge to point at. An interface-typed receiver stays
untyped; I list adding them as a question for the owner.

## What I expect to get wrong

- A subclass instance passed as the declared type: the edge names the base's method
  (hence 0.9, not 1.0).
- The same-name constructor convention when the constructor stores something else
  under that name.
- Reassigned parameters (`repo = other`) keep their declared type.
- JavaScript gains little: express and lodash rarely write JSDoc types, so most of
  their receivers stay unknown; the gain is mainly TypeScript (zod, is).
