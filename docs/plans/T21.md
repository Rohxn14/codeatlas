# T21 plan: structural adapter scopes for C, C++ and C#

## C and C++: a function's node spans its definition

Upstream tags queries tag the `function_declarator` (`h(void)`), which ends before the
body, so no call is ever inside a function node and `_enclosing_key` falls back to the
module. The fix is in the adapter, not in the queries (upstream queries are never
edited):

- **Span.** When a tagged definition node is a `function_declarator`, walk up through
  declarator wrappers (`pointer_declarator`, `reference_declarator`,
  `parenthesized_declarator`, `attributed_declarator`) to the `function_definition`
  whose `declarator` field is that chain. If that `function_definition` has a `body`,
  the definition's node becomes the `function_definition`. One table,
  `_DEFINITION_HOLDERS = {"function_declarator": "function_definition"}`, keeps the
  rule out of language branches. The tagged node is replaced, never duplicated, so
  there is still one node per function.
- **Stays as today**: a prototype (`int h(void);` is a `declaration`, not a
  `function_definition`), `S() = default;` and `= delete` (a `function_definition`
  without a body), a function declarator inside a parameter list (not the definition's
  own declarator).
- **Keys stay stable.** The qualname comes from the name and the enclosing scopes,
  which do not change (the declarator's ancestors are the definition's ancestors). The
  signature, which feeds the `#hash` suffix of repeated names, is still computed from
  the declarator (`h(void)`), so `square#8e3e-2` keeps its key. One deliberate change:
  a struct or prototype written *inside* a function body is now nested under it
  (`f.S`), as nested definitions are in every other structural language.
- **Docstrings.** A comment above `int f(void) {` was the type's sibling, not the
  declarator's, so C functions had no docstrings; with the wider node they get one.

## The C prototype rule

`_read_shape` reads the node's text from its span. It used to call a function a
prototype when the first `;` after the declarator came before any `{`. Now that a
definition's span ends after its `}`, the next `int x;` would mark it as a prototype.
New rule: a span whose text ends with `}` is a definition; otherwise (a declarator) the
old `;`-before-`{` test applies. The qualifier (`C::z`) is still read from the text
before the first `(`, which now starts at the return type; the regex is anchored at the
end, so `std::string C::z` still yields `C`.

## C#: nested namespaces

`_imports` joins every `@package.name` with the names of the package declarations
around it (`namespace A { namespace B {} }` gives `A.B`), generic over languages. The
file records `attrs["packages"]`: the namespaces that directly hold a definition, in
source order (a wrapper such as `A` above holds nothing and is left out); when no
definition is inside any package declaration (Java's `package x;`, C#'s file-scoped
`namespace A;`), every declared package is kept. `attrs["package"]` stays the first, so
Java, Go, PHP and the context's `by_package` table are unchanged. The C# profile builds
its own namespace -> files table from `packages` (cached in `ctx.cache`), so `using A.B;`
reaches a file by any namespace it declares, and the same-namespace scope covers all of
them.
