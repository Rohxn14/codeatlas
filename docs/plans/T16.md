# T16 plan: structural framework, Java and Go first

## Approach and data structures
- `TagsAdapter` runs `queries/<language>/imports.scm` when it exists and emits `RawImport`s; `@package.name` goes to the module node's `attrs["package"]`. Capture names live in `queries/README.md`.
- `structural/` holds one `StructuralResolver`. Per run it builds a `Context`: `FileInfo` per file (path, package, defs by name, imports) plus lookups by directory and by package. A `Profile` (Java, Go) answers two things: `reach(file, import) -> Reach` (files an import reaches, or an external name, the qualifier it binds, the names it brings in unqualified) and the package scope of a file. Everything else is shared.
- Resolution order for a call, nearest scope first, first non-empty tier wins (a nearer definition shadows a farther one):
  1. qualifier bound by an import (`pkg.F`, `C.m`): members of the reached files; an external import gives `::external:<import>.<name>`;
  2. enclosing class chain, for unqualified, `this` or `super` calls (Java);
  3. the caller's file; 4. the package scope; 5. files reached by imports.
  Each hit is `IMPORT_SCOPED`, confidence 1 ÷ candidates. Nothing found, or no profile: `NAME_GUESS` among same-language functions anywhere, 1 ÷ candidates capped at 0.3. Nothing at all: the call stays raw.
- Examples. Go `fmt.Println(...)` in `server.go`: `fmt` is a standard-library import, so `-> ::external:fmt.Println`, 1.0. Go `srv.Handle("ada")` (`srv` is a variable): tier 3 finds `Server.Handle` in the same file, 1 candidate, 1.0. Java `validate(user)` in `UserService.save`: tier 2 finds `UserService.validate`, 1.0. Java `Util.slug(x)` with `import a.util.*;`: `Util` is found in the wildcard's files, then `slug` among its members.

## Decisions
1. **Go package imports**: one IMPORTS edge per file, 1 ÷ n each, because the contract wants Module targets and a Package node is not allowed. To keep big packages from flooding the graph: if the importing file calls into the package, edges go only to the files holding what it calls; otherwise to the first 10 files by name, with `attrs["files_in_package"]`. Java wildcards use the same rule.
2. **Name-guess cut-off**: 5 candidates (Q2 in `decisions.md` is unanswered). At 6 or more the guess is noise (confidence under 0.17), so the call stays raw.
3. **Java overloads and inner classes**: the tags tier gives overloads `Class.m#<hash of signature>`, inner classes `Outer.Inner`, and constructors no node at all. The resolver matches by `node.name`, so every overload is a candidate and shares the confidence: argument types are not in a `RawCall`, so overloads cannot be told apart. Honest 1 ÷ n is the rule.

## Tests
Imports queries on snippets (Java: plain, wildcard, static, static wildcard, package; Go: single, grouped, alias, dot, blank, package). Both profiles' `reach`. Resolver on the two sample projects, scored with `eval.oracle.score` against hand-labelled `expected_graph.json`. Ruby name guesses and the cut-off. `_signature`: deep Python and tags adapter give identical keys on repeated, commented definitions.

## Expect to get wrong
Variables whose type is unknown (`repo.save()` with several `save`s in scope get split confidence); methods inherited from a superclass in another file (fall to a name guess); Go identifiers shadowing an import name; Java same-name classes in two source roots; package name differing from the last path segment for an external Go import (guessed from the path).
