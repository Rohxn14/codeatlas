# T11 plan: cross-language HTTP linker

## Inputs and outputs

`HttpLinker.link(results, index, snapshot_id)` reads every `ParseResult.routes` (server) and
`ParseResult.http_calls` (client) and returns ROUTE nodes, HANDLES edges and CALLS_HTTP edges.
It never reads files: it sees only what the adapters recorded.

## URL normalisation (client side)

Steps, in order, shown on the fixture's `` `/api/users/${id}` `` (TypeScript, template):

1. `dynamic` URLs are expressions (`BASE + "/users/" + id`). Split on top-level `+`; a quoted or
   backtick piece contributes its text, a bare name contributes one parameter, except a bare
   name at the very start, which is a host prefix and is dropped. No text left: unmatched, reason `dynamic`.
2. Strip `scheme://host:port`. Remember the host.
3. Strip a leading `${API}` / `{BASE}` placeholder not preceded by `/` (a host prefix).
4. Cut the query string and fragment (`?`, `#`).
5. `${...}` and `{name}` become one parameter segment `{}`.
6. Collapse `//`, drop a trailing `/` (decision 3: yes, `/api/users/` matches `/api/users`), ensure a leading `/`.

`/api/users/${id}` becomes segments `api, users, {}`. Compared case-sensitively.

## Matching and confidence

Compare segment lists of equal length. A route's `{param}` matches any client segment; a route
literal matches only an equal client literal; a client parameter never matches a route literal.

| Case | Resolution | Confidence |
| --- | --- | --- |
| client path has no parameter, equals route path, method equal | `ROUTE_EXACT` | 0.9 |
| any parameter involved on either side (template, or literal `/users/999` against `/users/{id}`), method equal | `ROUTE_PATTERN` | 0.7 |
| method unknown (`None`) | `ROUTE_PATTERN` | 0.7 |

Route method `ANY` matches any call method (pattern level). The adapters already give `fetch`
without options method `GET`, so `None` means genuinely unknown.

## Decisions

1. **Several routes match one pattern call**: keep the most specific (most literal segments). If
   still tied (`/users/{id}` vs `/users/{name}`), link all tied routes with confidence split
   equally: 0.7 / n. Rejected: picking one arbitrarily (hides a real ambiguity).
2. **Full host** (`https://api.github.com/x`): stays unmatched with reason `external_host`, counted.
   `localhost`, `127.0.0.1`, `0.0.0.0`, `testserver` hosts are stripped and matched. CALLS_HTTP is
   Function → Route in the contract, so an EXTERNAL target would break it.
3. **Trailing slash**: ignored on both sides.

## Routes

One ROUTE node per distinct (METHOD, path_pattern), key `{handler file}::route:{METHOD} {path}`,
the first handler in path order owning the key. Every handler gets a HANDLES edge (STRUCTURAL,
1.0). A module-key handler (inline Express arrow) gets the route but no edge, and a line in `problems`.

## Router prefixes

FastAPI and Flask prefixes are already joined by the Python adapter. Express mounts live in other
files and a `RawCall` carries no arguments, so `app.use("/api", router)` cannot be read:
**cross-file Express mounts are a v1 limitation**, reported in the explainer.
