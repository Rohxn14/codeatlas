# T12 plan: impact engine and test selection

## Approach
`impact(store, snapshot_id, changes, config) -> ImpactResult`. A `Change` is a path plus optional line ranges (from `parse_diff`), or explicit symbol keys (what the agent passes).

**Changed symbols.** For each range, the innermost FUNCTION, CLASS, INTERFACE or TEST whose span holds each changed line (exact: the innermost node can only change at a node boundary, so I test the range start and each boundary inside it). Lines outside any symbol (imports, top-level code) map to the module node. A file with no symbols maps to its module node. A file with no line ranges (a new, deleted or unknown file) maps to its module plus every symbol in it. A path not in the snapshot gives a warning.

**Four signals**, each gives a score in (0, 1] per target node, with its evidence:
1. **graph**: reverse walk over CALLS and IMPORTS from the changed symbols, `store/graph.py`'s `reverse_reach`, depth 4. To get the decay per hop without editing `graph.py`, the walk runs on a copy of the graph whose edge confidences are multiplied by the decay; a path scores `product(confidence) * decay^hops`. The best path is rebuilt from the score map (an edge whose far end scores `score / confidence`). Owner classes of a changed method are extra starting points at `decay` (imports point at the class, not the method).
2. **import**: modules with an IMPORTS edge into a changed file. An import of a changed symbol (or the module, or the owner class) scores `confidence * decay`; an import of an unchanged symbol in the same file scores half that (the file changed, the thing it imports may not have).
3. **co-change**: CO_CHANGES edges out of the changed modules; score = history confidence * `cochange_weight`; evidence is `support` and `source_commits`.
4. **convention/tests**: TESTS edges into a changed or reached node: `reach(dst) * confidence * tests_decay`. `reach` is 1.0 for a changed node, else its graph score.

**Combine.** Per target, `max` over signals (v1, "highest signal"), or `noisy_or` over the best score of each *signal* (so three paths in the graph signal do not stack, but graph plus co-change agreeing do): `1 - prod(1 - s)`. A switch, `combine="max"|"noisy_or"`. Default is picked from the mutation-truth F1, reported in the pull request.

**Tests.** A test target is a TEST node, or a module that is a test file (has TEST nodes, or `repo.test_conventions.classify` says so). Its score is the combined score, so a test is picked through a TESTS edge, through its CALLS to something reached, through importing a changed module, or through co-change. Evaluation aggregates to files (best score per file), since mutation truth is failing test *files*.

## Decisions
1. **Depth 4, decay 0.8.** Four hops at 0.8 leaves 0.41 for a perfect-confidence chain, still above a name guess; five or more hops are below 0.33 and dominated by noise on real call graphs. The decay is the only thing that keeps a long chain of 1.0 edges below a short, weaker one. Both are config fields and are not tuned further than a small sweep.
2. **Q3 (weak signals)**: unanswered by the owner, so the answer is "do not add paths inside one signal (they share one cause), but do let different signals agree (noisy-or)", with "max" kept as the switch. The failure case: a test that is imported and co-changed only because it is a giant shared helper scores high from two weak signals.
3. **Weak TESTS edges**: count at `confidence * 0.9`. D-23 already removed name guesses, so what is left is convention (0.8) and direct or import-scoped links; they are evidence the author intended the test to cover the code, so they get nearly full weight. Co-change weight is 0.7 because history is correlation, not dependency (Q5).

## Evaluation
`impact/evaluate.py` plus `scripts/evaluate_impact.py`. Mutation truth: change = the mutated function's span (found by key in a fresh index of the benchmark source), truth = failing test files; precision, recall, F1 at the natural cut-off (score >= `threshold`), k=5 and 10, share of tests skipped; caught-by-nothing mutants reported apart (Q4). Baselines: all tests; tests importing the changed module; co-change alone. Co-change: `ImpactPredictor` in `eval/cochange/predictors.py`, one index of HEAD, history read to each held-out commit (no re-index).

## Expect to get wrong
Precision. Tests reach most of a small library through a few hub functions, so a changed hub makes every test "affected" and the engine over-selects. Dynamic dispatch, decorators and fixtures that the resolvers cannot see give missed tests. Name guesses below 0.3 still carry weight on a long chain. Co-change after a refactor points at files that no longer depend on each other.

## Outcome (added at the end)
Default test cut-off set to 0.3 (best F1 on both mutation benchmarks; 0.5 and 0.7 lose recall). `noisy_or` selected the same tests as `max` at 0.3 and was not adopted. Both choices were made on the two benchmarks they are scored on.

## T12f fixes (added)
The review's fixes: HANDLES and CALLS_HTTP are walked; `parse_diff` keeps renames (new and old path), binary and mode-only changes, reads hunks by their line counts, and handles headerless diffs and git-quoted names; a range that touches top-level lines adds the module; `ImpactConfig` requires 0 < decay < 1 and `_trace` keeps a visited set. Evaluation: the co-change index is built at the parent of the oldest held-out commit, and the mutation report adds leave-one-benchmark-out for the cut-off. Numbers are in the T12f pull request and the explainer.
